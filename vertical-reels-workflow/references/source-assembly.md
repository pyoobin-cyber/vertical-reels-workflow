# 촬영 정리와 검수

## 1. 대상 원본과 현재 상태

새 작업인지 기존 편집을 이어가는지 먼저 구분한다. 기존 작업이라면 열려 있는 프로젝트·타임라인과 최신 저장본을 확인하고 새 버전을 만든다. 사용자가 지운 클립이나 마커를 과거 원본 목록으로 복구하지 않는다.

두 촬영 폴더와 콘티를 읽어 대상 영상에 속하는 파일을 분류한다. 제외한 파일과 이유를 기록한다. 파일명·폴더명만으로 카메라 역할을 정하지 않고 실제 화면에서 확인한다. 단일 앵글이나 추가 앵글이 주어진 경우 그 범위에 맞게 트랙을 구성하고, 없는 상대 앵글을 가정하지 않는다.

에이전트가 유지할 최소 기록은 다음과 같다. 형식은 현재 환경에 맞는 Markdown·CSV·JSON 중에서 정하며, 아래 기록이 특정 실행기를 자동 작동시키는 스키마라고 가정하지 않는다.

| 기록 | 내용 |
| --- | --- |
| 원본 목록 | 클립 ID, 실제 경로, 길이, 해상도, 정확한 fps, 음향, 색공간, 카메라 역할, 포함·제외 근거 |
| 콘티 대응 | 장면 ID·순서, 원본 또는 싱크 그룹, 대표 동작, 배치 근거, 미확인 항목 |
| 싱크 | 클립 간 시간차, 값의 단위·부호, 확인한 지점과 근거, 검수 상태 |
| OK 구간 | 클립 ID, 원본 기준 시작·끝, 동작 이름, 선택 이유 |
| 구도·색 | 회전·확대·위치, 입력 색공간과 변환, 추가 보정 노드, 검수 결과 |
| 실행·저장 | 프로젝트·타임라인 버전, 적용한 작업, 결과 경로, 미완료 항목 |

원본과 작업 결과 폴더를 구분하고 원본 파일의 이름·내용·위치를 변경하지 않는다.

## 2. 실제 화면 검수와 OK 선택

모든 대상 원본의 시간별 컨택트시트를 실제로 본다. 컨택트시트 도구가 없으면 영상 재생으로 확인한다. 후보 구간은 더 촘촘한 샘플 또는 원본 재생으로 검수한다.

초점, 손·물체 가림, 촬영 리셋 동작, 구도, 동작의 시작과 끝, 콘티 적합성을 보고 OK 구간과 사유를 기록한다. 밝기·흔들림 점수만으로 OK를 확정하지 않는다. 쓸 만한 구간이 없으면 억지로 표시하지 않고 이유를 남긴다.

OK는 클립 내부 마커로 표시한다. 파랑을 기본으로 사용할 수 있으나 프로젝트의 기존 규칙을 우선한다. 상단 타임라인 마커와 구분하고, 마커를 이유로 원본 길이를 줄이지 않는다. Finder 태그나 파일명 표시는 별도로 수행하지 않았다면 완료 항목에 넣지 않는다.

## 3. 싱크 확인

음향 파형, 슬레이트·박수 등 기준 동작, 화면상의 동일 동작을 비교한다. 파일 생성 시각은 후보 탐색에만 활용하고 싱크 증거로 단정하지 않는다. 무음, 짧은 촬영, 반복되는 동작·음악은 특히 화면과 소리의 복수 지점으로 대조한다.

시간차는 단위와 부호를 명시한다. 예를 들어 `side_start - top_start`의 양수는 사이드 녹화가 늦게 시작했다는 뜻이다. 서로 다른 fps의 원본 프레임 번호를 그대로 빼지 말고 실제 시간 또는 정한 타임라인 기준으로 환산한다. 긴 촬영은 시작·중간·끝에서 드리프트를 확인한다.

검증된 연결만 같은 싱크 그룹으로 묶는다. 하나의 긴 원본에 상대 앵글 여러 파일이 대응하면 원본을 복제하지 않고 한 그룹 안에 연결한다. 오프셋이 모순되거나 같은 트랙에서 원본이 겹치면 해당 배치를 실행하기 전에 근거와 트랙 구성을 다시 검토한다.

## 4. 원본 전체 길이와 콘티 배열

촬영 정리 타임라인은 하나를 기본으로 하며, 이름은 프로젝트에 맞게 정한다. 탑/사이드 촬영은 V1/A1 탑, V2/A2 사이드를 기본으로 사용한다. 음향 채널이 더 필요하면 전용 트랙을 추가하고 원본 채널과 영상의 연결을 기록한다.

- 선택한 각 원본을 처음부터 끝까지 한 번씩 배치한다. 소스의 전체 시간 구간과 음향을 보존한다.
- 싱크 그룹의 모든 영상·음향을 같은 양만큼 이동해 내부 시간차를 유지한다. 영상 하나만 움직여 싱크를 깨뜨리지 않는다.
- 촬영 시각이나 파일명보다 콘티·스토리보드 순서를 최종 배열의 기준으로 삼는다. 한 장면의 반복 테이크는 함께 정리하고 기록한다.
- 여러 장면을 담은 원본은 대표 장면에 배치하고 다른 장면과의 연결도 적는다. 장면별로 원본을 자르거나 복제하지 않는다.
- 미확인·단독 촬영도 같은 타임라인에 전체 길이로 보존한다. 콘티 대응이 불확실하면 검수 기록에 남기고 확인된 장면과 구분해 배치한다.
- 그룹 간 간격은 정리용으로 정한다. 이 간격이 실제 촬영 시각 차이라고 보고하지 않는다. 상단 그룹 마커는 요청 시에만 만든다.

컷 편집을 별도로 요청받으면 정리본을 보존한 새 편집 버전에서 필요한 구간을 선택·트리밍·재배열한다. 촬영 정리의 전체 길이 보존 기준과 이후 편집 요청을 혼동하지 않는다.

## 5. 세로 구도와 추가 노드 색보정

실제 화면을 보고 클립별 회전·확대·위치를 결정한다. 탑뷰에 동일한 회전각이나 확대값을 일괄 적용하지 않는다. 주요 피사체·손·동작과 자막이 들어갈 공간을 확인한다.

입력 색공간과 현재 프로젝트의 색 관리를 먼저 확인한다. 로그 원본은 해당 입력에 맞는 LUT·색공간 변환을 적용하고, 이미 변환된 원본에는 중복 적용하지 않는다. Sony SLog3/SGamut3.Cine와 같은 특정 조합은 해당 원본일 때만 선택한다. LUT가 없다고 다른 변환을 임의 적용하거나 색 검수를 통과 처리하지 않는다.

**각 클립에 색보정용 노드를 하나 추가한다.** 이 노드에서 하이라이트와 섀도우를 조정해 밝은 영역의 디테일이 날아가거나 어두운 영역이 뭉개져 묻히지 않도록 정리한다. 노드에는 역할을 알아볼 수 있는 이름을 붙이고, 작업을 이어갈 때는 기존 보정 노드를 식별해 수정한다.

노드의 위치는 현재 변환·색 관리 구조에 맞춰 정하고 실제 순서를 기록한다. 보정 전후 화면과 파형·스코프 등 사용 가능한 검수 도구를 함께 확인한다. 모든 클립에 같은 수치를 복사하지 않고 노출·화이트밸런스·채도, 피사체의 질감, 앵글 간 색을 맞춘다. 촬영 시 이미 소실된 디테일을 복구했다고 주장하지 않는다.

## 6. 실제 앱 검수와 저장

스크립트가 생성됐다는 사실과 앱에 적용됐다는 사실을 구분한다. 검수 중 임시 이동·트랙 비활성화를 했다면 확인 후 원상복원한다.

- 미디어가 연결되고, 원본마다 전체 구간이 한 번씩 배치됐는지 확인한다.
- 콘티 순서와 싱크 그룹 내부 오프셋이 유지되는지 확인한다. 상단 영상이 아래 영상을 가리면 트랙을 전환해 양쪽을 본다.
- 클립 이동 시 연결된 영상·음향과 OK 마커가 따라오는지 확인한다. Resolve의 Linked Selection 상태도 확인한다.
- 서로 겹치는 현장음은 한쪽씩 들어 싱크를 확인하고, 최종 청취 시의 트랙 활성 상태를 기록한다.
- 구도, 입력 변환, 추가 색보정 노드, 하이라이트·섀도우 디테일을 실제 화면에서 확인한다.
- 프로젝트를 저장하고 필요한 경우 DRP를 내보낸다. 저장·내보내기 결과와 경로를 확인한다.

실행 실패 시 실패한 프로젝트나 원본을 자동 삭제하지 않는다. 원인을 확인하고 새 버전으로 이어간다. 적용 완료와 시청·청취 검수 완료를 나눠 보고한다.
