# 세로릴스 제작 워크플로

다빈치 리졸브(Resolve)에서 촬영본을 정리하고, 필요하면 애프터 이펙트(After Effects)의 모션 자막과 연결한다. 특정 브랜드·컴퓨터·카메라·기존 프로젝트에 의존하지 않는 공유용 스킬이다.

이 패키지는 **에이전트의 작업 지침**이다. 편집 앱, 앱 제어 연결, 실행 스크립트, LUT, 폰트, AEP 템플릿은 포함하지 않는다. 현재 환경에 실제로 제공되는 파일·영상 분석·앱 제어 기능을 확인하고 가능한 범위에서 실행한다. 사용 가능한 기능이나 작업 완료를 추정하지 않는다.

## 시작점과 작업 범위

- 새 촬영 정리: 대상 영상의 두 촬영 폴더 또는 파일 목록, 콘티·스토리보드, 작업 폴더를 확인한다. 기존 대화와 파일에서 찾고 실행에 필요한 누락 정보만 묻는다.
- 기존 편집·자막 수정: 현재 타임라인, 최신 편집 파일·AEP, 변경 지시에서 시작한다. 완료된 촬영 정리를 반복하지 않는다.
- 콘티가 없으면 원본 확인·싱크 후보 검토는 진행할 수 있다. 콘티 배열은 미확인으로 남기고 장면 순서를 임의로 새로 만들지 않는다.
- 새 촬영 정리는 고유 이름의 새 프로젝트를 만들고, 기존 작업은 현재 상태를 저장한 뒤 새 버전에서 이어간다. 원본 미디어는 읽기만 한다.
- 검수 기록과 필요한 스크립트는 에이전트가 작성한다. 사용자에게 코드나 JSON 작성을 맡기지 않는다.

작업 흐름은 **대상 원본 분류 → 전체 길이 보존·싱크·콘티 중심 배열·OK 표시 → 세로 구도·색보정 → 요청한 컷 편집 → 모션 자막 → 투명 자막 출력 → 합성·음향·최종 출력**이다. 요청된 단계만 수행한다.

## 핵심 기준

1. **원본 전체 길이 보존:** 해당 영상으로 선택한 원본만 각각 한 번씩 배치한다. 여러 작품이 섞인 폴더의 모든 파일을 가져오지 않는다. 촬영 정리 단계에서는 원본의 앞뒤를 자르거나 분할하지 않는다.
2. **콘티 중심 배열:** 영상은 자르지 않되 콘티·스토리보드의 흐름을 중심으로 배열한다. 싱크가 연결된 원본은 그룹 내부의 시간차를 유지하며 함께 이동한다. 한 원본이 여러 장면에 걸치면 대표 장면에 배치하고 나머지 연결을 기록한다.
3. **두 앵글 한 타임라인:** 기본은 V1/A1 탑뷰, V2/A2 사이드다. 폴더명보다 실제 화면으로 역할을 판단한다. 다른 두 앵글이면 실제 역할을 정해 같은 구조로 대응한다. 원본 음향이 여러 트랙이면 필요한 트랙을 확보하고 영상과의 연결을 유지한다.
4. **검증된 싱크:** 파형 후보를 여러 지점의 화면·소리와 대조한다. 불확실한 쌍을 확정하지 않는다. 대상 영상의 미확인·단독 원본도 같은 타임라인에 전체 길이로 보존하고 사유를 기록한다.
5. **클립 내부 OK 표시:** 모든 대상 원본을 실제로 검수해 쓸 구간과 이유를 정하고 클립 마커로 표시한다. OK 표시는 원본을 자르라는 지시가 아니다. 상단 타임라인 그룹 마커는 요청할 때만 추가한다.
6. **추가 노드 색보정:** 각 클립에 `HL_SH_fix`라는 이름의 시리얼 노드를 하나 추가한다. 이 노드에서는 Primaries의 Lift/Gamma/Gain 대신 **Log Wheels 또는 HDR Palette의 Highlight·Shadow 컨트롤**을 사용해, 밝은 부분이 날아가거나 어두운 부분의 디테일이 묻히지 않도록 명암을 정리한다. 조정값은 클립별 실제 화면과 파형 스코프를 보고 정한다. 동일 작업을 이어갈 때는 이름으로 이 노드를 식별해 수정하고 반복해서 쌓지 않는다.
7. **현재 편집 상태 우선:** 사용자가 삭제한 클립·마커나 수정한 자막을 이전 목록·스크립트로 되살리지 않는다. 최신 상태와 변경 지시를 기준으로 필요한 부분만 수정한다.

## 규격과 색 관리

사용자가 지정한 납품 규격과 기존 프로젝트 설정을 우선한다. 새 프로젝트에 별도 지정이 없을 때는 **세로 9:16, 2160×3840, 30000/1001(약 29.97fps), SDR Rec.709 Gamma 2.4**를 기본값으로 제시하고 적용값을 기록한다. 해상도·fps·색공간을 모든 작업에 고정하지 않는다.

> **해상도 기본값에 관해:** 기본 2160×3840은 브랜드 광고·캠페인용 마스터 작업을 전제로 한 값이다. 디지털 사이니지·재편집·크롭 여유를 위해 마스터는 크게 만들고 SNS 납품본은 다운스케일한다. 일반 릴스·쇼츠 납품만 목적이면 사용자가 **1080×1920**을 지정하는 것이 렌더 시간·용량 면에서 합리적이며, 이 경우 타임라인 해상도 변경과 구도 재확인을 기록한다.

실제 소스 fps, 가변 프레임레이트 여부, 오디오, 로그/색공간 정보를 확인한다. 소스와 타임라인 fps가 다르면 해석·리타이밍·프레임 변환 방식을 정하고 길이·동작·싱크를 검수한다. 29.97을 30으로 묵시적으로 대체하거나 모든 소스 프레임이 1:1 대응한다고 보고하지 않는다. 에펙과 자막 출력은 대상 타임라인의 정확한 fps에 맞춘다.

카메라 로그 변환은 실제 입력 색공간에 맞는 LUT 또는 색공간 변환으로 처리한다. 이미 표시 색공간으로 변환된 영상·AI 영상·자막에 카메라 로그 변환을 중복 적용하지 않는다. 변환과 추가 보정 노드의 역할을 구분하고 실제 노드 순서와 결과를 확인한다. 노출·화이트밸런스·채도와 두 앵글 간 색도 맞춘다.

## 단계별 상세 절차

- 원본 분류·싱크·콘티 배열·OK·추가 노드 색보정: [촬영 정리와 검수](references/source-assembly.md)를 읽는다.
- 에펙 자막 수정·컷 변경 반영·투명 출력·합성: [자막과 최종 전달](references/captions-delivery.md)을 읽는다.

앱을 조작하기 전 현재 프로젝트와 재생·렌더·사용자 조작 상태를 확인한다. 사용자가 조작 중이면 충돌하는 작업을 멈춘다. 스크립트는 현재 환경의 실제 API와 대상 파일에 맞게 검토한 뒤 실행한다. 화면·포커스를 추정해 콘솔에 코드를 입력하지 않는다.

앱 제어가 없으면 가능한 분석·작업 기록·실행 자료를 준비하고, 실제 앱에서 남은 단계를 구체적으로 전달한다. 파일 생성, 앱 적용, 시청·청취 검수, 최종 출력을 구분해 보고한다. 별도 미리보기 렌더는 검수에 필요하거나 요청된 경우에만 만든다.

## 완료 확인과 보고

요청 범위에 맞춰 원본 연결, 전체 길이·중복 없음, 콘티 순서, 싱크, AV 링크와 OK 표시의 이동 추종, 세로 구도, 추가 색보정 노드와 명암 디테일을 실제 앱에서 확인한다. 자막·출력까지 작업했다면 그 결과도 화면과 소리로 확인한다.

완료한 작업, 결과 파일 위치와 연결된 버전, 실제 검수한 항목, 미확인·남은 작업을 짧게 전달한다. 외장 미디어 미연결이나 앱 기능 부재를 완료로 처리하지 않는다.
